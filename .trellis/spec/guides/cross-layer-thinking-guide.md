# 跨层检查指南

VOZEB PRO 的典型链路为：

```text
页面/组件 -> hook/store -> services/api -> app/api route
          -> lib/server -> database repository 或文件 provider
```

画布、资产和 AI 任务还可能经过服务端项目 API、服务器媒体目录、导入导出包或外部 provider。

## 改动前

- 列出输入、输出、错误、状态码和每层数据类型。
- 搜索所有消费者，包括浏览器持久化、管理后台、画布、站内 Agent 和文档。
- 标出不可破坏的 URL、JSON 字段、持久化 key、任务状态、计费语义和包格式。
- 决定验证归属：外部输入在边界验证，业务不变量在应用/领域层，数据库约束在持久层。
- 新增或调整角色/职责权限时，必须同时列出页面分区、导航与按钮、可编辑字段、客户端请求 payload、Route Handler、RSC/API 响应序列化和数据库查询七个边界；不能只隐藏入口或只在服务端返回 403。一个页面承载多类职责时，展示和提交都按当前职责拆分，响应不得继续下发无权分区的密钥、地址或内部配置。
- AI 规划输出属于不可信建议：先明确用户本轮原文、显式选择、历史记忆各自的优先级，再由服务端归一化任务类型、目标实体和参数；不能让规划器漏字段或历史摘要覆盖当前明确输入。
- 生成尺寸既是请求契约也是结果契约：先按“本轮文字明确尺寸 > 当前精确自定义宽高 > 本轮参考图比例 > Agent 规划 > 后台默认”解析任务参数；Canvas 的当前精确尺寸可能位于配置节点 `metadata.size`，根级 `imageSize` 仍是后台默认比例，服务端必须按真实紧凑快照读取选中/连接或唯一精确配置，不能只测试理想化根字段；图片使用精确 `宽x高` 时还要在服务器落盘前读取上游文件真实宽高并规范化，不能以请求体字段正确代替最终文件验收。
- Canvas 发送本轮参考素材时，只能替换旧的媒体节点选择，必须保留配置、文本等非媒体节点选择；否则紧凑快照虽然包含 `metadata.size`，服务端仍无法判断哪个配置属于本轮请求。
- 同一字段承载不同语义时先拆契约，例如“文本节点原位编辑”和“媒体节点作为参考素材”必须分别建模，不能靠前端位置或 ID 前缀推断。
- 生成工作台的“用户原文”和“上游执行提示词”必须分别建模并贯穿 UI、请求快照、持久化和历史恢复；执行提示词可以用于创建与显式重试，但不得作为标题、搜索文案、用户消息或会话上下文的展示回退。
- 可见消息不能只依赖 `role` 推断；工作台服务端写入、数据库/文件 Provider 查询和客户端恢复必须共同校验显式公开标记，未标记内容按内部数据拒绝展示。
- 区分“内容相同”和“请求相同”：用户主动重复提交必须生成新的稳定请求身份；幂等重放只认同一个请求 ID；显式重试复用原业务记录但创建新的上游尝试。任何会话、消息或生成日志关联都不得按提示词文本匹配。
- 区分“当前生成记录”和“当前创作对话”：图片/视频工作台每轮主动提交仍写入独立记录，但结果展示要按 `creativeConversationId` 聚合该对话的全部记录；展示聚合不能反向覆盖持久记录，结果操作必须携带 `recordId + resultId` 回到真实所有者。
- 区分“停止观察”和“停止任务”：切换 Agent 对话只关闭旧页面的 SSE 订阅并清空旧会话视图，不能调用取消、暂停、重试或重新创建；后台 Run、子任务和上游任务继续使用原稳定身份运行。
- 所有可能跨越会话切换返回的请求都要携带会话身份与页面代次，回调写 UI 前同时校验两者；Run 控制请求还要把预期 `conversationId` 交给服务端核对，不能只相信当前组件里的 `runId`。
- 点击新建对话时必须在任何创建请求 `await` 之前推进页面代次、停止旧 SSE 观察并使旧 `conversationId` 失效；创建失败才显式恢复原会话。不能等新会话返回后再切换身份，否则旧 Run 回调或旧提交响应仍可能短暂写入当前视图。
- 若触及兼容格式，先添加 round-trip 或特征测试。
- 删除嵌入其他聚合快照的子实体前，列出“实体本体、父聚合引用、运行任务/事件、生成记录、媒体候选”全部所有者；删除 API 必须由服务端在同一事务或文件多锁回滚边界内同步移除父引用并返回权威状态，不能让客户端再发一次保存请求完成一致性。

## 改动后

- 验证空值、无权限、超时、失败、重试和回退 provider。
- 权限改动至少用两种单职责账号和一种全权限账号回归：断言无权入口/字段不存在、无权响应字段被移除或降为必要摘要、混合 payload 被拒绝、有权保存能往返恢复；不能以 DOM 隐藏代替 RSC/API 数据最小化。
- 验证自动创建的 UI 实体使用稳定领域身份执行布局、去重和重放，不依赖生成 ID 的展示前缀；同批实体也必须纳入下一项的碰撞与约束计算。
- 验证数据写入后能由现有版本路径读回。
- 验证主动相同内容重复提交、同请求 ID 幂等重放、历史 hydration 与显式重试四条路径使用一致的稳定身份，不会相互覆盖或制造重复记录。
- 验证同一 `creativeConversationId` 连续提交两轮后，当前结果框同时保留两轮；点击“新建对话”为空，切回和刷新恢复全部轮次；跨轮次删除或重试只修改目标记录。
- 验证 A 对话运行中切换 B 时，B 不显示 A 的消息、运行状态或停止按钮，A 不收到控制请求；延迟的 A Run 查询返回后仍不能在 B 建立 SSE，切回 A 只能续接原 Run，不能创建第二个 Run 或上游任务。
- 验证聚合子实体删除的主实体保护、跨用户/跨项目拒绝、最后一项替换、重复删除幂等、空输入归属校验，以及 PostgreSQL 任一语句失败和文件 Provider 任一写入失败时父引用与子聚合一起回滚。
- 对媒体生成同时核对任务参数、持久化资产元数据和实际文件尺寸/时长；上游忽略参数时应在可信服务端规范化或明确失败，不能让 UI 根据期望值伪造结果信息。
- 电商多资产分层要区分“通用单主体去背”和“上游一次返回多图的分层任务”：人物去背继续走本地语义分割；电商分层只提交一次唯一源图并消费同一任务的完整 `results[]`，不得再调用 bbox 识别、本地目标切片或逐元素图片任务。每个结果按 `taskId + resultIndex` 创建独立节点并由源图分别连线；平台不补固定数量或结果上限。上游元素层必须与源图同尺寸并保留坐标，服务端逐像素核对元素、重复覆盖和背景未覆盖区，落盘不得重采样；单张合成图、透明空洞图、重绘图或不完整背景不能冒充分层。
- 检查 UI 没有了解数据库 row，服务端没有依赖 React/Zustand。
- 检查计费/退款与任务状态在失败路径仍一致。
- 执行相关桌面、移动、画布或工作台浏览器回归。
- 对生成中的结果卡读取真实 `getBoundingClientRect()`；源码 class、DOM 存在或根容器无横向溢出都不能证明自动宽度 flex/grid 子项没有收缩成线。

不要把一次跨层需求变成跨域大重构。先通过兼容适配将新职责放到目标边界，再逐步迁移调用方。
